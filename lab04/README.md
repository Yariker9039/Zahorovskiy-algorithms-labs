## Пояснення

Повернув −1, хоча 55 є на індексі 5. Виконано 8 порівнянь із target.

Спочатку mid = 7, там 31. Оскільки 31 < 55, low стає 8: алгоритм одразу відкидає індекс 5, де є 55. Далі перевіряє індекси 11, 13, 14; low стає 15, high лишається 14, і пошук завершується без результату.

Перевірка впорядкованості потребує проходу по масиву — O(n). Якщо робити її перед кожним пошуком, загальна робота вже не буде O(log n). Впорядкованість краще забезпечити один раз заздалегідь.

Коли в тих самих даних треба багато разів щось шукати. Тоді один раз сортуємо, а далі використовуємо бінарний пошук. Для одного пошуку зазвичай простіше пройти список лінійно.

Лічильник рахує кожне порівняння з target окремо: == і, коли потрібно, <. Це не кількість ітерацій циклу.
